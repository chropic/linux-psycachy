## Proposed implementation approach and gates

1. Add an immutable overlay source identity (repository, target commit, range start, kernel base release/hash) and machine-readable manifest, preserving upstream blob IDs and SHA-256 file digests for imported inputs.
2. Reconcile each item above against exact CachyOS 7.3.1 source, then decide: already in baseline (with file/commit proof), superseded by later upstream, port/rebase, platform candidate, required camera implementation, or justified exclusion with source evidence. A read-only individual check of 37 final Surface/camera/PHY and selected audio/Wi-Fi patches found 26 apply and 11 do not apply alone to pristine 7.3.1; see the [applicability report](sp12-overlay-apply-check-952f769e-vs-cachyos-7.3.1-20261112.md). These results do not prove semantic coverage or an ordered series. The overlay target’s 7.3.3 version does not imply those patches apply to the local 7.3.1 pin.
3. Build a dependency graph/order from patch headers and series history for camera (CAMSS X1P42100, CCI, CSI2 DPHY, OV13858/OV02C10, DTS), USB/eUSB2/PHY, audio/DMIC, PCI/suspend, QSEECOM/EL2, Wi-Fi/rfkill, regulators, and Surface suspend. Integrate the required camera patches and Kconfig into the r2 series; source, build, DT, runtime, and hardware qualification remain separate gates.
4. The current build path now consumes the ordered manifest under its pinned digest, validates unique patch IDs and paths, and no longer requires `series == 10`. Refresh the manifest with the reconciled patch set and explicit target/profile while keeping ARM64 identity, SP12 DTB/package pins, and fallback policy tied together.
5. Require source/license/provenance review and targeted build/boot/hardware validation for any adoption. Camera implementation is required for r2 and remains incomplete until firmware, sensor wiring, graph endpoints, clocks/regulators/GPIO, media-controller config, and userspace pipeline are evidenced. Patch application alone does not establish runtime support.

## Gaps and cautions

- In the final ebuild, the changed SP12 patch files are dormant: only SurfaceGo2 HID/camera patches are passed to `PATCHES`. Do not interpret overlay tree presence as an enabled kernel series.
- The overlay range contains large supporting patch series (GPU GMU/IRQ_HPD, PCIe, PHY/eUSB2/USB, remoteproc/EL2, Iris/video, Wi-Fi, audio), many not directly Surface-named but potentially transitively necessary. The inventory table records all changed kernel patch/ebuild/Manifest paths; actual dependency closure remains unproven.
- Several files are deleted/replaced/renumbered across the range. The target snapshot and ordered ebuild application list govern; old revisions are superseded unless final series re-adds them.
- No kernel build, tests, or runtime validation were performed for this audit.
